# inpagerun

Run JavaScript inside real Chromium pages from the command line.

`inpagerun` can run a one-off snippet, or keep a page open and run multiple snippets against the same browser state.

## Requirements

- Node.js v24 or newer

## Install

```bash
npm install --global inpagerun
```

## Prepare

Before the first run, install Chromium for Playwright:

```bash
npx playwright install chromium
```

## Usage

Run once and close the browser:

```bash
inpagerun once -u <url> -c <code>
```

Open a persistent page:

```bash
inpagerun open <url>
```

Run code on a persistent page:

```bash
inpagerun --id <id> --code <code>
```

Close a persistent page:

```bash
inpagerun close --id <id>
```

## Agents and LLMs

If you are an agent or LLM, use the [inpagerun skill](https://github.com/XaveScor/inpagerun/blob/master/SKILL/inpagerun/SKILL.md) for guidance on running this CLI.

## One-Off Runs

```bash
inpagerun once -u https://example.com -c "console.log(document.title)"
```

Options:

- `-u, --url <url>`: page URL to open
- `-c, --code <code>`: JavaScript to run inside the page
- `--debug`: forward browser `console.debug(...)` output to stdout with a `[DEBUG]` prefix

## Persistent Pages

Open a page and keep it alive:

```bash
id=$(inpagerun open https://example.com)
```

Run code on the same page:

```bash
inpagerun --id "$id" --code "document.body.dataset.value = 'ok'"
inpagerun --id "$id" --code "console.log(document.body.dataset.value)"
```

Close the page:

```bash
inpagerun close --id "$id"
```

`open` starts a detached Chromium instance in headless mode by default. Use `--headed` to make the browser window visible:

```bash
inpagerun open --headed https://example.com
```

Use `--debug` with `open` to print diagnostic output to stderr:

```bash
inpagerun open --debug https://example.com
```

## Examples

Read the page title:

```bash
inpagerun once -u https://example.com -c "console.log(document.title)"
```

Read text from the page:

```bash
inpagerun once -u https://example.com -c "console.log(document.querySelector('h1')?.textContent)"
```

Run async code in the page:

```bash
inpagerun once -u https://example.com -c "console.log(await fetch('/').then((response) => response.status))"
```

Import local code:

```bash
inpagerun once -u https://example.com -c "const data = await import('./data.js'); console.log(data.default)"
```

Keep state between runs:

```bash
id=$(inpagerun open https://example.com)
inpagerun --id "$id" --code "window.count = 1"
inpagerun --id "$id" --code "console.log(window.count)"
inpagerun close --id "$id"
```

## How It Works

- Code runs inside the browser page, not in Node.js.
- You can use DOM APIs like `document`, `window`, and `fetch`.
- Async code works, so `await` is allowed.
- Static imports and string-literal dynamic imports are bundled before your code runs.
- Dynamic imports must use a string literal, for example `await import("./data.js")`.
- Node.js built-in modules like `fs` and `node:path` are not supported.
- `--code` runs as statements. The CLI does not print the last expression value.
- Top-level `return` is not supported. Use `console.*` to print values.

## Console Forwarding

- `console.log(...)` and `console.info(...)` are forwarded to stdout.
- `console.warn(...)` and `console.error(...)` are forwarded to stderr.
- `console.debug(...)` is ignored unless `--debug` is provided.
- With `--debug`, `console.debug(...)` is forwarded to stdout with a `[DEBUG]` prefix.
- Multiple console arguments are printed space-separated.
- Non-string values are serialized for terminal output.

## Persistent State

- Page ids are generated by `inpagerun`, for example `page_7x9a2c`.
- Persistent state is stored in a temporary directory.
- Page ids remain valid while the detached Chromium instance and page are open.
- `inpagerun close --id <id>` closes the page and cleans up Chromium when it was the last page.
